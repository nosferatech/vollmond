## Question

The session thought [C7](C7.md) had been read as being about older versions of vmd, while it is about other YAML tools. PyYAML,
Ruby (Jekyll) and old js-yaml read YAML 1.1, where `answer: no` is the boolean false, `2026-10-09` is a date and `1:30` is the
number 90; vmd reads all of them as strings. Does vmd's writer quote such strings so that those tools read them as strings too,
and does `vmd check` warn about unquoted ones in hand-written files? The versioning point of the owner's C7 note had its own card,
[F4](F4.md).

## Options

- **(a) Quote the full list, and warn in strict mode.** Chosen, as recommended. Files vmd writes read the same in every tool, and
  hand-written front matter such as `answer: no` is flagged. vmd carries its own quoting table.
- **(b) Quote only what YAML 1.2 misreads.** No extra code. Jekyll and PyYAML silently see `answer: no` as false.
- **(c) Full list, no warning.** Safe output; hand-written problems surface only when another tool reads the file.

## Decision

(a), as a setting. Compatibility quoting is on by default: the serializer quotes every string a common YAML 1.1 reader takes for
something else (the survey's full list), and `vmd check` warns about unquoted ones. A user who controls their tools may turn it
off explicitly, and that also turns the warning off. The owner's further point, that warnings can be configured by issue code,
is recorded as [F3a](F3a.md).

## Why

The card's reason: tickets and docs are read by other tools (GitHub's front matter table, Jekyll, scripts), and the cost is one
table. The owner's: quoting `no` while not quoting other strings is ugly, but it maximizes compatibility, so err on the side of
caution by default; a user who knows no YAML 1.1 tool reads the data may turn it off as an explicit decision, assuming the
responsibility. (b) lets YAML 1.1 tools misread silently; (c) catches hand-written problems only when another tool reads them.
