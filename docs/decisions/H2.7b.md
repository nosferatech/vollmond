## Question

Under [H2.7](H2.7.md)'s full lexical space, a NOTE in RFC 3339, section 5.6, lets applications separate the date and the time
with a space. The session asked: "Date-times written with a space instead of T, like 2026-10-09 08:00:00Z: RFC 3339 notes that
applications may allow the space, but its grammar, which JSON Schema validators check, doesn't. Accept it?"

## Options

- **(a) Reject it.** Chosen, as recommended. Follow RFC 3339's grammar, so vmd agrees with JSON Schema validators. Local
  date-times (TOML) still accept the space.
- **(b) Accept it.** Friendlier to hand-written dates, but a plain JSON Schema validator would then reject data vmd accepts.

## Decision

(a). `date-time` follows the RFC's `date-time` production, which JSON Schema validators check, so the space is rejected there,
while local-date-time keeps accepting it, as TOML 1.0.0 does.

## Why

The session's reasons, from the question's options: (a) keeps vmd in agreement with JSON Schema validators; under (b) a plain JSON
Schema validator would reject data vmd accepts.
