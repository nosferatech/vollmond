## Question

Writes from an app to a GitHub store: GraphQL `createCommitOnBranch` with its required `expectedHeadOid` gives a multi-file atomic
commit with compare-and-swap. The review named the limits (branch protection, GitHub's content-creation rate limits, a commit per
change) and said validation must run in the app before it commits. What does vmd assume?

## Options

- **(a) Validation must run server-side**, in the app, before it commits, as the review said.
- **(b) Server-side validation is ideal, and setups where only clients validate stay possible.** Chosen.

## Decision

(b). A repository used purely as a database need not have strong branch protection and can accept direct pushes. Write-protected
repositories (docs next to code) go through PRs and the merge queue, and the update process must comply. GitHub as a backend
assumes a low commit rate; high write throughput needs a specialized service. Server-side validation is ideal, but simple setups
where only clients validate must stay possible.

## Why

The owner's reason for (b): simple setups, where clients take responsibility for validation, should not be excluded. Why the other
options lost: Not recorded.
