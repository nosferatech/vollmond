## Question

Item 3 of card Y, from the pull request that implements cards P, Q, R and T (#94) and its independent review, which found
nothing blocking. [P3](P3.md)'s comment skip applies only to the title rule: `<!-- c -->` followed by a `toml data` block gives no
issue at all, which breaks [P6](P6.md) and [G3a](G3a.md). Does a comment-only HTML block count as the first block for the
misplaced-data-block rule?

## Options

- **(a) Comment-only HTML blocks do not count as the first block for the misplaced-data-block rule either.** Chosen, as
  recommended.
- **(b) Accept, except what the note says**, card Y's option (b): "The exceptions keep today's behaviour or get their own card."
  Today, `<!-- c -->` followed by a `toml data` block gives no issue at all.

## Decision

(a), as part of card Y's option (a), accepting all three: an HTML block that holds only comments does not count as the first
block of a record without a title heading, the same skip that P3 gives the title rule. So a `yaml data` block after such a
comment is `data-block-misplaced`, and a `toml data` block after it `feature-unsupported`; both follow from [P6](P6.md), which
detects a data marker wherever a data block can stand or is misplaced.

**Agent's reading, for the owner to confirm.** That this amends P3's comment skip in the same direction, and so supersedes it,
is this record's reading; the card does not say so. P6 and G3a are not superseded, since Y3 restores their rules rather than
changing them.

## Why

The card's reason for the item: without it, `<!-- c -->` followed by a `toml data` block gives no issue at all, which breaks P6
and G3a. For the card as a whole: it "closes two cheap gaps".

Why (b) lost: Not recorded.
