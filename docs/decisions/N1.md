## Question

The draft set no nesting limit for JSON and YAML. Both libraries recurse and crash on deep nesting, and YAML's results depend on
how deep the caller already is: 700 levels can crash. Python's standard JSON reader fails near 1,000. The JSON parser (#69)
refused nesting deeper than 1,000 as a `syntax-error` meanwhile, noting that RFC 8259, section 9, allows a limit, and that YAML
would need the same answer. What is the limit?

## Options

- **(a) One limit for every format, 256 levels**, refused as a `syntax-error`, written into §5.4 with suite cases at 256 and 257.
  Chosen, as recommended.
- **(b) 1,000 levels, the JSON parser's reading in #69.**
- **(c) No limit, as the draft stood.** Both libraries recurse and crash on deep nesting.

## Decision

(a), with card N's option (a), accepting every recommendation. Nesting is limited to 256 levels within each parse unit (a JSON
or YAML file, front matter, a data block), its top value counting as the first level, and a deeper value is a `syntax-error`
(§5.4, Appendix D), with cases at 256 and 257 levels in JSON and in YAML. It is counted per unit because a data block's value sits
deep in its record's value view.

## Why

The card's reason: real records never come close to 256, and the limit holds with room to spare even when called from deep
inside the Markdown parser. For the card as a whole: each rule follows YAML or C2 where they speak, and picks the safe reading
where they don't. Against (c), the card's statement of the problem: both libraries recurse and crash on deep nesting.
Why (b) lost: Not recorded.

## Applied in

Draft v0.9 (#73, `75c8728`), §5.4 and Appendix D; the YAML parser (#72, `24689e7`) and the JSON parser follow it.
[P1](P1.md) then put Markdown containers under the same limit, in a resource-limit clause for every format.
