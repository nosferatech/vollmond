## Question

The design of phase I2 reads the two keywords along a static "spine" of the schema: `properties`, `patternProperties`,
`additionalProperties`, `items`, `prefixItems`, `$ref` to a fixed location, `allOf`, and `x-vmd-list`'s own `items` and
`additional`. That lets vmd prove an address singular (§7.4, #15) before evaluating anything. `x-vmd-list` changes what an address
means and `x-vmd-ref` what a value is. Where may they stand?

## Options

- **(a) On the spine only.** Chosen, as recommended. A declaration reached only through `oneOf`, `anyOf`, `if`/`then` and the
  like is `schema-invalid`; unreferenced `$defs` are fine. When two `patternProperties` patterns bring unequal declarations to one
  member in the data, that member gets a `schema-violation`, and the rest of the collection is unaffected. A reference's meaning
  never depends on which `oneOf` branch its record satisfies; the proof stays static, and §9.3 says where the keywords may stand.
- **(b) Anywhere, as annotations.** The proof cannot be static for those levels, and a Python implementation would need annotation
  collection; whether Python's `jsonschema` can collect annotations is unverified.
- **(c) Anywhere, wherever met.** Failing branches included, as an Ajv custom keyword does, so meaning depends on branches.

## Decision

(a). The declarations are read along the spine, a declaration reached only off it is `schema-invalid`, and a member to which two
patterns bring unequal declarations gets a `schema-violation` and neither declaration.

## Why

The card's reason: "It keeps references' meaning static and the singularity proof possible; relaxing it later is an addition
under U21." The design adds that what an address means then never depends on which branch the data happens to satisfy, so the
proof of §7.4 can work from the schema alone. Allowing the keywords off the spine later relaxes a refusal that fails every read of
the collection under [U12](U12.md), so it is an addition under [U21](U21.md). (b) loses the static proof and asks of a Python
implementation what is not known to be possible; (c) makes meaning depend on branches.
