## Question

Item 1 of card X, from I2's configuration pull request (#91) and its independent review, which found nothing blocking. The code
keeps its current reading of each item until the owner decides. A schema file that cannot be read (permission denied, a
directory, a FIFO). Today it is `schema-invalid`, naming the reason. Appendix D's `schema-invalid` row covers "missing, over 1
MiB, not valid", and `storage-failed` names "refused by a permission error". Which code does an unreadable schema file get?

## Options

- **(a) `storage-failed`.** Chosen, as recommended, "so the code says what failed". The collection's records are still refused
  under [U12](U12.md).
- **(b) Keep today's reading: `schema-invalid`, naming the reason.** As the code does until the decision.

## Decision

(a), as part of card X's option (a), accepting every recommendation: a schema file that cannot be read is `storage-failed`, and
the collection's records are still refused under U12.

**Agent's reading, confirmed by the owner on [W3](W3.md) (item 1) for symbolic links, empty directories, directories with files in
them and the `--config` case; its FIFO part is superseded by W3.** The card listed "a FIFO" among the files that cannot be read.
Draft v0.12 says "a file of the store that the backend cannot read", and leaves what a backend reads as no file to the storage
contract, which #91 implements: in a store's own `.vmd/schema/`, the filesystem backend reads a symbolic link, a FIFO or an empty
directory as missing, so such a schema is `schema-invalid`, while a directory with files in it is `storage-failed`; beside a
`--config` file, whose schema directory is read without a backend, a FIFO or a directory is `storage-failed`. Whether a FIFO in a
store should be `storage-failed` too was left open. The owner answered it on W3, choosing to confirm the readings with the note
"fifo's in the store should cause failure, the don't belong there.": a FIFO in a store's `.vmd/schema/` is `storage-failed` too,
as anywhere in the store, while the rest of this reading is confirmed: a symbolic link and an empty directory still read as
missing.

## Why

The card's reason for the whole card: "Each removes a silent outcome or uses the code that names what actually went wrong."

Why (b) lost: Not recorded.
