## Question

Item 1 of card X, from I2's configuration pull request (#91) and its independent review, which found nothing blocking. The code
keeps its current reading of each item until the owner decides. A schema file that cannot be read (permission denied, a
directory, a FIFO). Today it is `schema-invalid`, naming the reason. Appendix D's `schema-invalid` row covers "missing, over 1
MiB, not valid", and `storage-failed` names "refused by a permission error". Which code does an unreadable schema file get?

## Options

- **(a) `storage-failed`.** Chosen, as recommended, "so the code says what failed". The collection's records are still refused
  under [U12](U12.md).
- **(b) Keep today's reading: `schema-invalid`, naming the reason.** As the code does until the decision.

## Decision

(a), as part of card X's option (a), accepting every recommendation: a schema file that cannot be read is `storage-failed`, and
the collection's records are still refused under U12.

## Why

The card's reason for the whole card: "Each removes a silent outcome or uses the code that names what actually went wrong."

Why (b) lost: Not recorded.
