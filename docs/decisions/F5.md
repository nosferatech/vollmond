## Question

On [C12](C12.md) the owner chose a rule of vmd's own over GitHub's, and on [C13](C13.md) asked to match GitHub for
"Title `<a id>`". The session objected that a "simpler" rule leaves about 10 percent of the captured headings with a different
anchor and gives an ASCII-only rule no anchor for Japanese or Greek headings, and proposed freezing GitHub's rule as captured
in October 2026 as vmd's own, versioned rule. The owner answered in chat that the rule is vmd's own and does not chase GitHub,
and asked for a rule defensible on its own merits. The session proposed one, each step with its own reason: slug the text a
reader sees; normalize to NFC and drop invisible characters; lower-case each code point, with the Unicode version pinned;
trim, then turn every kind of whitespace into a hyphen; keep letters, marks, decimal digits, `_` and `-`, without collapsing
hyphens; number repeats with the smallest unused suffix, counting only vmd sections. Under it, the `<a id>` element is not part
of `$title` (§5.3), so the space before it is trimmed. Which variant of the rule?

## Options

- **(a) Adopt this rule.** Chosen, as recommended (V2 in the session's measurements). Anchors depend only on what the reader sees,
  are unique, and contain no invisible characters. About 89 percent of headings get the same anchor as on GitHub; a link copied
  from GitHub to a heading with unusual whitespace, decomposed letters, invisible characters or unsupported HTML may not resolve,
  and strict mode suggests an explicit anchor there.
- **(b) The same, but collapse runs of hyphens.** Prettier anchors (`fish-chips` instead of `fish--chips`), but only 72 percent
  agree with GitHub, and `a - b` collides with `a b`, so one of them gets `-1`.
- **(c) The same, but only U+0020 is a space.** 91 percent agreement. A no-break space or tab is dropped instead of becoming a
  hyphen, so a heading typed with a no-break space gets a different anchor from the same heading typed with a space.

## Decision

(a), given in chat. Agreement with GitHub is a bonus, not a goal. vmd does not follow later GitHub changes, and changing vmd's
rule requires a spec version, warnings first and a migration. The rule (§6.3) takes the text a reader sees, normalizes it to
NFC, removes default-ignorable code points, lower-cases per code point, trims, keeps letters, marks, decimal digits, connector
punctuation and `-`, turns white space into `-`, and numbers repeats by skipping used candidates, among vmd sections only. For
C13: the `<a id>` element is stripped, then the title is trimmed, so there is no trailing hyphen, and the serializer writes the
element without a space.

## Why

The card's reason: every step is defensible on its own; the one concession to GitHub, not collapsing hyphens, also has its own
merit (distinct anchors) and is worth 17 percentage points of agreement. The log's: F5 kept the captured handling of rendered text
and of Unicode, so that most links copied from GitHub still work, and made the rule vmd's own and versioned. (b) costs 17 points
of agreement for appearance and makes `a - b` collide with `a b`; (c) makes the anchor depend on invisible spacing differences.
The log corrects a figure of fact (#8): measured against the 673 GitHub anchors captured in #37, the rule as decided agrees on 528
(78 percent), and on 602 (89 percent) only as it stood before C13 and C14.
