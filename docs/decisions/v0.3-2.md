## Question

The owner asked the draft to say which value types a node supports: either the intersection of YAML and JSON, or extra types,
with their canonical form defined in each representation. Common types (date, time) might belong in the standard, enabled by
default, and the interpretation of numbers, int64 and bigints included, needs defining, with a survey of what common JSON parsers
support.

## Options

- **(a) The intersection of YAML and JSON only.**
- **(b) The intersection, plus standard extra types with a canonical form in each representation.** Chosen: the core types are the
  JSON data model as I-JSON restricts it, and logical types are declared with JSON Schema's `format`, as OpenAPI does.

## Decision

(b). Value types are specified: the I-JSON subset of JSON, rules for numbers, and standard logical types declared with `format`
(date, time, date-time, duration, int64, bigint, decimal, and more). Which number forms common parsers support needs a survey.

## Why

The owner's reason: there are a number of common types that everyone needs, worth including in the standard and enabled by
default, and number interpretation is ambiguous without rules. Why (a) lost beyond that: Not recorded.
