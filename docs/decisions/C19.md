## Question

A selector is an address that may match several nodes, such as a path through a level that allows repeats, a tag, or a query
(§7.4). Selectors feed queries and references that the schema declares as having many targets. The spec did not say what happens
when one matches nothing (suite question 9). For example, a selector for every section tagged `decision`, run on a ticket that
has no decisions yet.

## Options

- **(a) An empty result.** Chosen, as recommended. `resolve` succeeds with an empty list, just as a query with no matches does.
  Whether a many-reference with no targets should be flagged is left to the reference rules of §8.5, which call a reference with
  no target dangling.
- **(b) A failure.** `resolve` fails with a no-match issue, which catches a mistyped tag at once. Every caller must treat "nothing
  yet" as an error, and a selector behaves differently from a query that means the same thing.

## Decision

(a). A selector that matches nothing returns an empty result, not a failure.

## Why

The card's reason: as the suite recommends, for consistency with queries. (b) makes every caller treat "nothing yet" as an error.

## Applied in

Draft v0.4 (#50, `1043a6c`), §7.4. G5 later made an empty many-reference valid (§8.5).
