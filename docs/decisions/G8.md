## Question

[F3](F3.md)'s compatibility quoting covers strings that YAML 1.1 readers misread. Numbers can be misread too: a hand-written
`017` is 17 to vmd and 15 to PyYAML, and vmd's own writer could emit `1e-7`, which YAML 1.1 reads as a string because it has no
dot. Should compatibility quoting also cover numbers? The question came from the independent review of #50 (Draft v0.4).

## Options

- **(a) Yes, in F3's spirit.** Chosen, as recommended. Under compatible quoting, vmd writes exponents with a dot and a sign
  (`1.0e-7`), and a new warning flags hand-written numbers that YAML 1.1 reads differently (`017`, `1e3`). Both go off with
  `yaml_quoting: minimal`.
- **(b) No, strings only.** Simpler; a PyYAML or Jekyll reader may see a different number or a string, with no warning.

## Decision

(a). The writer uses exponent forms that a YAML 1.1 reader also reads as numbers, with a dot in the mantissa and a sign on the
exponent (`1.0e+20`), and `vmd check` warns about other number forms that YAML 1.1 readers misread (§4.2, §4.4). As an extension
of F3, `yaml_quoting: minimal` turns off this warning, `yaml-ambiguous-number`, as it turns off the string warning. Two readings
of the session, accepted when it was applied: the warning covers every plain number a YAML 1.1 reader misreads (`017`, `0o17`,
`1e3`), not only exponent forms, and the writer uses the same number form in JSON and Markdown, not only in YAML.

## Why

The card's reason: the same reasoning as F3, to maximize compatibility by default and let a user who controls their tools turn
it off. The card's consequence for (b), not a reason it gives against it: a PyYAML or Jekyll reader may see a different number
or a string, with no warning.
