## Question

§6.2 told authors to put the anchor element at the end of the heading, after a space. GitHub keeps that space when it builds the
slug, so the derived anchor ends in a hyphen (slug report, item 2; suite question 11). For example, the heading
`## What was done <a id="done" class="decision"></a>` has the explicit anchor `done` and the GitHub anchor `what-was-done-`;
written without the space, it renders the same on GitHub and gives `what-was-done`. The section's key is `done` in every option,
since an explicit anchor takes precedence (§5.5); the choice affects only the derived anchor of headings that carry an explicit
one. Accept the trailing hyphen GitHub derives from "Title `<a id>`"?

## Options

- **(a) Accept it.** Recommended. vmd computes `what-was-done-` exactly as GitHub does, and §6.2's example and the serializer stay
  as they are. Links normally use the explicit anchor (`#done`), so the odd form matters only to someone who copies GitHub's
  permalink, and that link resolves in vmd too.
- **(b) Write the element without a space.** §6.2's example, the serializer and vampiredb's migration change to
  `Title<a id="x"></a>`, and strict mode warns about a space before the element. Derived anchors look clean, but the heading
  source is harder to read and every existing heading written with a space must be edited.
- **(c) Drop the hyphen in vmd only.** vmd computes `what-was-done` while GitHub emits `what-was-done-`. Links copied from GitHub
  to such headings are dangling in vmd, and links vmd suggests do not work on GitHub, which breaks the follow-GitHub rule.

Chosen: neither at first. The owner answered Other: do exactly what GitHub does, declare both forms equally valid, and recommend
writing the element without a space. After [C12](C12.md) made the slug rule vmd's own, the owner settled it in chat with
[F5](F5.md).

## Decision

On the card, the owner's Other: follow GitHub, with or without the space. In chat, on the follow-up F5, the owner ignored GitHub
instead: the `<a id>` element is not part of the heading's title and is stripped before trimming, so
`## What was done <a id="done"></a>` gives `what-was-done` with or without the space, never a trailing hyphen. The serializer
writes the element without a space. GitHub's behavior, which keeps the hyphen, is ignored. The log records this final rule
under C13.

## Why

The card's reason for (a): the slug report left this to the owner, and the recommendation was the session's; choose (b) if the
derived anchors of explicitly anchored headings are expected in links often. The owner's first answer followed GitHub. Once the
rule was vmd's own (C12), the session pointed out that in vmd the element is not part of `$title` (§5.3), so the space before it
is ordinary trailing space and is trimmed; the owner agreed. Why (b) and (c) lost: Not recorded.
