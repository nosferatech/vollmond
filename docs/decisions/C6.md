## Question

Two number forms are valid JSON and valid YAML 1.2 but sit at the edge of what a double can hold, and parsers disagree on both
(survey §5.5). `-0` is negative zero in JavaScript, and plain 0 in Python's `json`, Jackson and `serde_json`'s exact mode.
`1e400` is larger than any double: JavaScript and the `yaml` library read it as Infinity, js-yaml and PyYAML read it as a string,
and `serde_json` refuses it; Infinity is outside the data model, as §4.1 already rejects YAML's `.inf`. For example, one file
says `offset: -0` and another `limit: 1e400`: what should `vmd get --value` print for each, and does either file pass check?

## Options

- **(a) `-0` is 0, and `1e400` is an error.** Chosen, as recommended. `-0` reads as the number 0, so `offset: -0` and
  `offset: 0` are equal and hash alike, while the bytes `-0` stay in the file because unchanged numbers are never rewritten.
  `1e400` is outside the data model in every mode, like `.inf`, because there is no double to fall back to, so parse fails on it.
  `1e-400`, which a double rounds to 0, is an ordinary exact-only number under C4 and C5.
- **(b) `-0` is 0, and `1e400` is just exact-only.** As (a) for `-0`, but `1e400` follows the general rule of C4. Under C4 (a) in
  lenient mode that leaves a value with no double at all, so it needs a special case anyway, and the same file is readable in
  lenient mode and not in strict.
- **(c) `-0` stays negative zero.** `-0` and 0 become different values in equality and queries. Python, Java and Rust's exact
  mode drop the sign when parsing, so each implementation needs extra code, and RFC 8785 (the canonical JSON behind node
  versions) writes `-0` as 0, so two unequal values would share a version token.

## Decision

(a). The follow-up [F2](F2.md) folded it into one rule for numbers, which also makes a non-zero value that underflows to zero
(`1e-400`) an error.

## Why

The card's reason: the survey leaves both points open; (a) keeps every value a finite double, matches what most parsers already
do with `-0`, and treats `1e400` like `.inf`, which §4.1 already rejects. Why (b) and (c) lost: Not recorded; their
consequences are under Options.
