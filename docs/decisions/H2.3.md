## Question

Item 3 of card H2, from #52 Q5. §4.1 forbade custom tags. Read literally, YAML's own tags are allowed: `!!str 12` is the string
"12", while `!!binary`, `!!set` and `!foo` are errors, and the `yaml` package reads `!!str 12` and the non-specific `! 12` (YAML
1.2.2, section 6.9.1) as the string `"12"` and resolves `!!set` and `!!binary` even in the core schema (parser survey, section
4.2). Is every explicit tag an error, or only tags outside the core schema? The card marked it as a change to the draft, not a
reading of it.

## Options

- **(a) Every explicit tag is an error (`yaml-tag`).** Chosen, as recommended. `!!str` and the non-specific tag `!` included.
- **(b) Keep the draft's literal reading: only tags outside the core schema are errors.** `!!str 12` and `! 12` stay valid, as
  the strings the `yaml` package makes of them.

## Decision

(a), with card H2's option (a), accepting every recommendation. Every explicit YAML tag is an error, core schema tags such as
`!!str` and the non-specific tag `!` included (`yaml-tag`). This changes the rule: Draft v0.4 rejected "custom tags", which read
literally left `!!str 12` and `! 12` valid (§4.1, Appendix D).

## Why

The card's reason: quoting does the same job, vmd never writes tags, and it keeps one way to write a value. The log's: quoting
already forces a string, and the value view cannot keep a tag. The session noted, when the review of #52 raised it, that (a) is
a change to the spec and put it to the owner as one. Card H2's reason for accepting every recommendation: each keeps vmd strict
and its output readable back, and none contradicts an earlier decision.

## Applied in

Draft v0.5 (#57, `d0d1424`), §4.1 and Appendix D. [N6](N6.md) later made an undeclared tag handle, such as `!e!x`, a
`syntax-error` rather than `yaml-tag`.
