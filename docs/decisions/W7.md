## Question

The card: "The strict read mode (PR #146, merged) and Draft v0.16 had to fill in details your AJ and AK answers left open. Each is
labelled "Agent's reading, for the owner to confirm" in the decision records and the I2 design. Confirming makes them decided; any
you reject becomes its own card. Ones a user would notice are marked (cost)." [AJ](AJ.md) and [AK](AK.md) are those answers. The
card lists six:

1. **A refused read reports only why it was refused.** The card: "A strict `get` of a record with a schema violation and a
   duplicate anchor fails with the schema violation alone, not with every error the record has."
2. **Strict `refs` across the store reports every record it couldn't return (cost).** The card: "those the mode refuses, and also
   those with broken structure or a file that couldn't be read. Each is reported by every issue it was refused for, so a record
   with 50 schema violations gives 50 errors. Over collections whose schemas can't be used, it fails, naming each such schema
   once."
3. **A strict `ls` counts refused records with the unreadable ones,** the card: "as it already does for broken ones, without
   saying why each was refused."
4. **The read mode is chosen once, when the store is opened,** the card: "not per call."
5. **A record two collections claim is read unchecked, even in strict mode (cost).** The card: "The draft's list of what strict
   mode refuses doesn't include that conflict, so a strict caller gets data no schema checked (the conflict is still reported by
   `vmd check`)."
6. **`refs` from or to a refused record.** The card: "`vmd refs --from` a refused record fails, as a strict `get` of it does;
   `vmd refs --to` it lists the links into it, with the statuses they have in the default mode (your AJ answer)." This is AK's
   reading.

Items 1 to 5 are #146's readings 1, 2, 3, 4 and 6; the I2 design's section 4.6 labels items 1 and 2. #146's reading 5, that
`Store.binding` stays independent of the mode as public API, was not on the card, and stays the implementing agent's reading,
for the owner to confirm.

## Options

- **(a) Confirm all six.** Chosen, as recommended. The card: "The labels come off in the next draft. Nothing in the code
  changes."
- **(b) Confirm, except what the note says.** The card: "Each exception becomes its own card."
- **(c) Discuss first.** The card: "The readings stay labelled."

## Decision

(a): all six readings are confirmed. AK's record says so for item 6, and the I2 design's section 4.6 for items 1 and 2. #146's
reading 5 is not among them.

## Why

The card's reason: "Each follows the draft's written list of what strict mode refuses, or what a query already does. Item 5 is
the one to look at twice: a strict reader can still get an unchecked record when two collections claim it; refusing it would add
a code to the list (decision G7)."

Why (b) and (c) lost: Not recorded.

## Owner's note

The project owner chose (a) on the review desk on 2026-10-20, with no note.
