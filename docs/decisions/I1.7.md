## Question

Item 7 of card I1, from #57's open questions: the draft allowed block anchors "outside container blocks", which read literally
excludes a nested list item, since list items are containers. Can a nested list item, or an `<a id>` at the start of a list item's
second paragraph, carry a block anchor?

## Options

- **(a) An anchor may start any list item at any depth, and a paragraph only at the top level.** Chosen, as recommended. An
  `<a id>` starting a list item's second paragraph gets the `anchor-element-ignored` warning.
- **(b) Keep the draft's words read literally: no block anchor inside a container, so none in a nested list item.**

## Decision

Card I1's option (a), accepting every recommendation. A block anchor may stand at the start of any list item, at any depth, and of
a paragraph only at the top level. An `<a id>` starting a list item's second paragraph gives `anchor-element-ignored` (§6.2,
Appendix D). The log left one reading open, to the owner: whether a list item inside a block quote can carry a block anchor is not
settled by "any list item at any depth".

## Why

The card's reason: nested task lists are common in tickets, which the literal reading (b) would leave without block anchors.

## Applied in

Draft v0.6 (#58, `c3879b7`), §6.2 and Appendix D. [J2](J2.md) closed the open reading in Draft v0.7: a list item inside a block
quote carries no block anchor. [T](T.md) later widened the rule to any paragraph outside block quotes.
