## Question

A selector returns every match, and the draft does not say in what order. The code returns the first step's member and
child-section matches, then its anchors in document order, and then follows each step (#83, its tenth open question). In what
order does a selector return its matches?

## Options

- **(a) Document order.** Chosen, as recommended.
- **(b) Keep the draft as it is.** No order is specified.

## Decision

(a), as part of card R's option (a), accepting every recommendation: a selector returns its matches in document order.

## Why

The card's reason: results are then stable across implementations.

Why the other options lost: Not recorded.

## Applied in

Draft v0.11 (#87, `169c597`): §7.4, §10.5 (document order is the pre-order of Q2), the conformance README (a selector's matches
and a reference's `targets` are compared in order), the runner's comparison of `resolve` results.
