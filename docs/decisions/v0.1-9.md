## Question

The review's git points: use the git blob SHA as the record version token; defer Level 3, since custom merge drivers run only in
local git, never in GitHub's merge button or merge queue; and validate in CI, not only in hooks, since hooks are not installed by
`clone` and do not run for commits made through the API. Which does vmd adopt?

## Options

- **(a) The review's three points.** Chosen: blob SHAs as version tokens, Level 3 (merge drivers) deferred, validation in CI.
- **(b) Merge drivers in the first version**, as Draft v0.1's Level 3 had them; they would run only in local git.

## Decision

(a). Merge drivers are deferred. When a store is in git and publishes its index, the index should be published whatever made the
commit and whoever made it.

## Why

The review's reasons: merge drivers never run in GitHub's merge button or merge queue, and in the session's words they are also
the most expensive parts to build, with semantic diff. Hooks do not run for every commit, so validation and publishing cannot rely
on them.
