## Question

The plan's §1.1 put a TypeScript runner inside `conformance/`. The suite README keeps runners with their implementations, so that
`conformance/` holds data only and an implementer in another language finds nothing language-specific there (suite question 20).
For example, a Python implementer copies `conformance/`: under one option the copy includes a `package.json` and TypeScript code
they do not need. Where does the TypeScript conformance runner live?

## Options

- **(a) In the workspace, next to the implementation.** Chosen, as recommended. The runner is part of the TypeScript workspace
  (#19), plan §1.1 changes accordingly, and `conformance/` needs no `package.json`. The suite stays data only and can be vendored
  into other projects as it is.
- **(b) In `conformance/`, as the plan says.** The runner sits beside the data it reads, but the suite then carries TypeScript
  code and a `package.json`, and the README's data-only rule changes.

## Decision

(a), with the owner's note. Each language's conformance runner lives next to that language's implementation, and the
conformance data stays language-neutral and shared.

## Why

The card's reason: as the suite recommends. The owner's: the runner should stay next to its language, and data that can be
language-agnostic is best shared across languages. (b) puts TypeScript code into the data-only suite.

## Owner's note

> data was shared across languages
