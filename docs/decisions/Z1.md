## Question

From the references pull request (#99). The Markdown limits refuse a `.md` record that nests deeper than 256 levels or has more
than 4,096 emphasis runs in a paragraph, and since card Y ([Y1](Y1.md), [Y2](Y2.md)) a data `$title` that does so. A JSON or YAML
record's `$body` holds Markdown text too, but the spec does not cover it, so such a record reads normally. #99 parses a data
`$body` for links only when it needs references; past the limits the parser gives up, the links are silently missing, and `check`
reports no broken references about links it never read. The card's example: a `$body` of 300 `>` followed by `[x](missing.md)`
reads fine and reports nothing, while the same text in a `.md` file is a `syntax-error`. Until the owner decides, #99 records the
silence as a deviation and pins it with a test. Do the limits apply to a data `$body`?

## Options

- **(a) Apply the limits to a data $body.** Chosen, as recommended. The card: "Such a record gets a `syntax-error`, like a `.md`
  file and a data `$title`. One rule for all Markdown text. Draft v0.13 and a suite case; small code change."
- **(b) Report an issue at the $body, keep the record readable.** The card: "A new warning or error code at the `$body`. The
  record's other data stays readable, but its body's links are still unknown."

## Decision

(a): a JSON or YAML record whose `$body` passes the Markdown limits of §5.4, nesting or runs, is a `syntax-error`, as a `.md`
record and a data `$title` are.

**Agent's reading, confirmed by the owner on [W4](W4.md) (items 4, 5 and 10).** Three details the card leaves open, which Draft
v0.13 states as follows: the `syntax-error` is at the record's root, as a data `$title`'s is ([Y2](Y2.md), confirmed on
[W3](W3.md)); every limit on Markdown holds in a `$body` as in a Markdown file, the nesting of containers and of inline elements
and the runs of each paragraph, table cell and heading, in every section's `$body`, the root's included; and this extends Y1's and
Y2's limits in the same direction, and so supersedes them, as they superseded [P1](P1.md). The suite's cases past a limit pin the
first two readings: each expects its `syntax-error` at the root, and `data-section-body-nesting-257-json` puts the text in a
section's `$body`.

## Why

The card's reason: "It's the rule card Y already chose for titles, and the same text in a `.md` file is refused. A reader
shouldn't return text it can't fully parse."

Why (b) lost: Not recorded. The card's consequence for it: the body's links are still unknown.
