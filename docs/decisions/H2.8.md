## Question

Item 8 of card H2, from #52 Q10's first point. §4.4 warned on YAML 1.1 booleans such as `yes` and `true` "in any case", but YAML
1.1 reads only `yes`, `Yes` and `YES` (likewise `true`, `on` and the others) as booleans, and no YAML 1.1 reader reads `tRuE` or
`yEs` as one. Warn on every casing, or only on those?

## Options

- **(a) Warn on exactly the casings YAML 1.1 reads, so `tRuE` gets no warning.** Chosen, as recommended. In #52's words, the
  list of §4.4 is the exact set for strings.
- **(b) Keep "in any case", as drafted**: warn on `tRuE` and `yEs`, which no YAML 1.1 reader reads as booleans.

## Decision

(a), with card H2's option (a), accepting every recommendation. The boolean and null entries of §4.4's list cover exactly the
casings YAML 1.1 reads (`yes`, `Yes`, `YES` and the like, from the regular expression of its bool type), so `tRuE` gets no
warning, and "in any case" is gone. The list also drives compatibility quoting, which therefore no longer quotes `tRuE`; no reader
misreads it. The null entry gains `Null` and `NULL`, which is the agent's reading and not on the card, confirmed by the owner on
[W12](W12.md) (2026-10-20), its item 3: YAML 1.2's core schema and YAML 1.1 both read them as null, so Draft v0.4's list missed
strings that the serializer must quote.

## Why

The card's reason: YAML 1.1 reads only those three casings as booleans. The log's: no reader misreads `tRuE`. Card H2's reason
for accepting every recommendation: each keeps vmd strict and its output readable back, and none contradicts an earlier decision.
Why (b) lost: Not recorded.

## Applied in

Draft v0.5 (#57, `d0d1424`), §4.4. Since the list drives [F3](F3.md)'s compatibility quoting, it narrows that quoting for other
casings and widens it to `Null` and `NULL`.
