## Question

[K3](K3.md) decided `--config` for the I1 design and the plan, and the CLI foundation (#74) implemented it, but the draft's list
of global options in §12.1 did not have it. Does the draft record it?

## Options

- **(a) Add it to §12.1 and the decision log.** Chosen, as recommended.

Other options: Not recorded.

## Decision

(a), with card O's option (a), accepting every recommendation. `--config PATH` is a global option (§12.1), using a file in place
of the store's `.vmd/config.yaml`. It records in the draft the flag that the I1 design's question 3 (K3) brought into task I1.8,
with the store discovery it implies (§3.3): `--store` names the root, without it the root is the nearest directory at or above
the working directory holding `.vmd/config.yaml`, and with `--config` the root need not hold one. As a consequence, `vmd set`'s
option for a JSON value, which clashed with the global `--json`, is renamed `--json-value`.

## Why

The card's reason: K3 had decided it, and the spec's list of global options did not have it. For the card as a whole: each rule
makes the CLI predictable for agents and keeps anchors stable across Node versions.

Why the other options lost: Not recorded.

Draft v0.10 (#78, `d1e0a60`), §3.3 and §12.1.
