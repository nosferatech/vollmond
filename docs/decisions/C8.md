## Question

An empty Markdown file is a record with no title, fields or sections. An empty YAML file is null to the `yaml` library and to
PyYAML, and an error to js-yaml 5; an empty JSON file is a syntax error in every JSON parser. A record's root must be an object
(§5.1), so the spec had to say whether an empty YAML file, or one holding only comments, is the empty record (survey §8). For
example, a script creates `tickets/0200-new.yaml` as an empty file, or with only a `# TODO` comment line, before filling it in.
Does `vmd check` pass it?

## Options

- **(a) Empty YAML is the empty record; empty JSON is an error.** Chosen, as recommended. A YAML file with nothing but whitespace
  and comments has the value view `{}`, the same as an empty Markdown file. A YAML file whose content is null, a number or a list
  is still an error, and JSON stays strict because an empty file is not JSON. One special case in the YAML parser and one fixture
  per format.
- **(b) Both are errors.** The root must be an object in every format, with no special case. An empty placeholder YAML file
  fails check until someone writes `{}` into it, and the same empty record is valid as Markdown but not as YAML.
- **(c) Both are the empty record.** Most forgiving, but vmd would accept a `.json` file that no JSON tool can read, which breaks
  the promise that a record is a plain file other tools understand.

## Decision

(a). An empty YAML file is the empty record, and an empty JSON file is an error.

## Why

The card's reason: the survey only notes that the case needs a fixture, and the recommendation is the session's; it treats YAML
like Markdown, where empty means empty, without making vmd accept invalid JSON. (b) makes the same empty record valid as
Markdown but not as YAML; (c) accepts a `.json` file no JSON tool can read.
