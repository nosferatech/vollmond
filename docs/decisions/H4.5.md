## Question

An anchor element that is not at the start of a paragraph or list item, as in `Book <a id="room"></a>the room.` mid-paragraph,
or inside a block quote as `> <a id="q"></a>Quoted`, could be a block anchor, an anchor element subject to
`anchor-element-invalid`, or plain HTML. (#53, question 14.)

## Options

- **(a) Plain HTML, not an anchor, with a warning.** Chosen, as recommended. An anchor element only at the start of a paragraph
  or list item outside container blocks.
- **(b) A block anchor.**
- **(c) An anchor element subject to `anchor-element-invalid`.**

## Decision

(a), as card H4's option (a), accepting every recommendation. An anchor element that is not at the start of a paragraph or list
item outside container blocks is plain HTML and anchors nothing, with a warning under a new code, `anchor-element-ignored`
(§6.2).

## Why

The card's reason for the warning: the writer probably meant an anchor. Why the other options lost: Not recorded. The card's note
for the six items: each recommendation keeps vmd strict and its output readable back, and none contradicts an earlier decision.

## Applied in

Draft v0.5 (#57, `d0d1424`), §6.2 and Appendix D (`anchor-element-ignored`, a warning, named by the author). Whether a nested
list item, or an `<a id>` at the start of a list item's second paragraph, can carry a block anchor was left open (#57's open
question 7), and [I1.7](I1.7.md) settled where a block anchor goes; J2 and T refined it further.
