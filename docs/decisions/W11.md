## Question

The card, "Details of the local index (the cache) that no card settled": "The local index (PR #153) and Draft v0.18 filled in
these details. Each is labelled for you to confirm. Confirming makes them decided; any you reject becomes its own card. Ones a
user would notice are marked (cost)." The card lists eleven; the records or documents that hold them are added in parentheses:

1. **A cache that can't be used is skipped with no warning** (cost). When vmd refuses an `XDG_CACHE_HOME` (your AT rule), it runs
   as if `--no-cache` were given and says nothing. A dotfiles user who sets `XDG_CACHE_HOME=$HOME/.cache` explicitly silently gets
   no cache. If you'd rather vmd print a one-line warning, say so in the note. ([AT](AT.md), reading 1)
2. **A `.git` file counts as a checkout** (submodules, worktrees), and the default directory is still refused at or below the
   store root (AT). (AT, reading 1)
3. **An absolute `XDG_CACHE_HOME` is used on macOS too;** a relative one is ignored (AT; a deviation from the design, recorded on
   #25). (AT, reading 2)
4. **`ls` with a glob counts the unreadable records the glob matches across every page,** and reports each broken collection
   schema once. (#153's reading 2)
5. **A strict `ls` counts from each record's parse, not the cache,** so it gets no speed-up (cost; the commands task may revisit
   it). (#153's reading 3)
6. **With `--config` naming a configuration in another checkout, a cache set inside that checkout is used.** Whoever can commit
   there already controls the configuration and schemas, so it adds no new hole. (#153's reading 4, in the I2 design's section
   6.2.1)
7. **Cache entries keep only what vmd reads locally,** not every column of the portable index (deviation on #25). (#153's reading
   5, deviation 10 on #25)
8. **The cache's id covers all of core's source, tests included, and the lock file,** so any change to them starts the cache cold.
   (#153's reading 6)
9. **An entry or snapshot over 128 MiB is a miss, and so is any entry that fails to restore.** (#153's readings 7 and 8)
10. **Each record's entry is capped at twice the record's size (at least 64 KiB),** so the cache never uses more memory than
    parsing (cost: records of many tiny values are parsed every run; #156 proposes a compact format). (#153's reading 9, deviation
    11 on #25)
11. **A cache implementation may declare a smaller bound** (`IndexCache.maxEntryBytes`), for the planned cloud backends. (#153's
    reading 10)

## Options

- **(a) Confirm all eleven.** Chosen, as recommended. The card: "The labels come off in the next draft. Nothing in the code
  changes."
- **(b) Confirm, except what the note says.** The card: "Each exception becomes its own card (item 1's warning would be a small
  code change)."
- **(c) Discuss first.** The card: "The readings stay labelled."

## Decision

(a): all eleven readings are confirmed. AT's record says so for items 1 to 3. Items 4 to 11 are #153's readings, which no record
or draft sentence labels; this record holds their confirmation. So an unusable cache stays silent, as the card's outcome says.

## Why

The card's reason: "Each is what the reviewed code does, chosen for safety or for memory. Item 1 is the one to look at twice: a
warning would tell a dotfiles user why their cache is off, at the cost of a line on every run."

Why the other options lost: Not recorded.

## Owner's note

The project owner chose (a), "Confirm all eleven", on the review desk on 2026-10-20, with no note.
