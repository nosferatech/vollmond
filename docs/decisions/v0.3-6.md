## Question

Open point 3: a section's data and an example in documentation look alike, both being fenced YAML blocks. How is a section's data
told apart? The owner first asked whether this was the distinction between fences and `---` blocks; the session answered that the
two delimiters each have one place, front matter `---` at the start of the file only and fences for sections, so the question is
about fences only.

## Options

- **(a) A marker word, ```` ```yaml data ````.** Chosen, as the session recommended. GitHub highlights both kinds as YAML, since it
  reads only the first word of the info string, and moving a record between collections never changes its value.
- **(b) The schema decides**: plain ```` ```yaml ```` blocks, and the collection's schema names the sections that carry data. The
  same file then parses differently depending on its collection, and a record outside any collection, or an implementation that
  does not load schemas, sees no data at all.
- **(c) Position decides**: the first YAML block after any heading is data. An example that opens a docs section silently becomes
  a field of that section.

## Decision

(a). Data blocks are marked ```` ```yaml data ```` (or `json data`). Front matter is `---` at the start of a file only; sections
use fences.

## Why

The session's reasons: (a) fits how GitHub already reads info strings, while (b) and (c) each turn existing example blocks into
data, and (b) also makes a file's value depend on its collection.
