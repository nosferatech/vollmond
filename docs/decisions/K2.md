## Question

Question 2 of the phase I1 design (#59), item 2 of card K. [C2](C2.md) asks for every error, but a recovering parser's later
errors are often cascades caused by the first, and the suite expects one issue for a syntax error. How many syntax errors does a
parse report?

## Options

- **(a) One `syntax-error` per parse unit (a file, the front matter, each data block), while the other units are still parsed.**
  Chosen, as recommended. That still meets C2's "report every error" across units.
- **(b) One issue per library error.**

## Decision

(a), through card K's option (b), which accepted every recommendation but question 3's. One `syntax-error` per parse unit, a file,
its front matter or one data block, while the other units are still parsed (§9.2, Appendix D). This refines C2's "every error",
which [F1](F1.md) kept. The suite README's rule for case authors now speaks of parse units.

## Why

The design's and the log's reason: a recovering parser's later errors after a syntax error are mostly cascades, and the suite
expects one issue for one. The card adds that (a) still meets C2's "report every error" across units. The design's section 3.1:
"a recovering parser's tree past an error is a guess", which is why (b) would report cascades.
