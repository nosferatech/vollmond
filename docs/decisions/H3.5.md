## Question

What do empty front matter, an empty data block, and front matter that is not an object give? The Markdown fixtures (#54,
question 5) asked with empty front matter, a sequence or a scalar between the delimiters, and an empty `yaml data` fence right
after a heading. An empty YAML document is null.

## Options

- **(a) Empty gives no fields, in both places; front matter that is not an object is `data-block-not-object` at `""`.**
  Chosen, as recommended. `root-not-object` stays for JSON and YAML files.
- **(b) Empty is a not-an-object error.**
- **(c) Non-object front matter is `root-not-object`,** §5.4's code for records.

## Decision

(a), as card H3's option (a), accepting every recommendation. Empty front matter, or an empty data block, gives no fields. Front
matter that is not an object is `data-block-not-object` at `""`; `root-not-object` stays for JSON and YAML files (§5.3,
Appendix D).

## Why

The PR's reasons: an empty one gives no fields as §5.4 makes an empty YAML file `{}`, and non-object front matter is
`data-block-not-object` since the decision log of Draft v0.2 calls front matter the root's data block. Why the other options lost:
Not recorded. The card's note for all sixteen items: each recommendation keeps vmd strict and its output readable back, and none
contradicts an earlier decision.

## Applied in

Draft v0.5 (#57, `d0d1424`), §5.3 and Appendix D. P7 later gave a `json data` block of only white space no fields, "as an empty
block does (H3.5)".
