## Question

[F6](F6.md) lets a YAML or JSON reference's schema require an explicit anchor (`x-vmd-ref` with `anchors: explicit`). The draft
read it as: the fragment must begin with an explicit anchor. That accepts `#done/notes`, where `notes` is a key derived from a
title, so a retitle still changes what the reference means, which is what the setting exists to prevent. How strict is
`anchors: explicit` on a reference? The question came from the independent review of #50 (Draft v0.4).

## Options

- **(a) No step may resolve through a title-derived key or anchor.** Chosen, as recommended. `#done/notes` is rejected unless
  `notes` is an explicit anchor or a field name; field names and keyed-list keys stay fine. A reference with the setting never
  changes meaning when a title changes.
- **(b) Only the first step must be an explicit anchor, as drafted.** Simpler to check, but a retitle deeper in the path still
  retargets the reference silently.

## Decision

(a): `anchors: explicit` means that no step of the address resolves through a title-derived key (§9.3).

## Why

The card's reason: it gives the guarantee the setting promises. The card's consequence for (b), not a reason it gives against
it: simpler to check, but a retitle deeper in the path retargets the reference silently.

## Applied in

Draft v0.4 (#50, `1043a6c`), §9.3. [G10](G10.md) then also forbade positional steps under `anchors: explicit`.
