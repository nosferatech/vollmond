## Question

Item 3 of card X, from I2's configuration pull request (#91) and its independent review, which found nothing blocking. The code
keeps its current reading of each item until the owner decides. Case conflicts between directories. `Docs/a.md` and `docs/a.md`
give `path-case-conflict`, but `Docs/a.md` and `docs/b.md` do not, although macOS and Windows merge the two directories. Do
directories that differ only in case conflict?

## Options

- **(a) Compare every prefix of the path case-insensitively.** Chosen, as recommended, so directories that differ only in case
  conflict too. §3.2 says so.
- **(b) Keep today's reading: only whole paths are compared.** `Docs/a.md` and `docs/b.md` do not conflict, although macOS and
  Windows merge the two directories.

## Decision

(a), as part of card X's option (a), accepting every recommendation: every prefix of a path is compared case-insensitively, so
directories that differ only in case give `path-case-conflict`.

## Why

The card's reason for the whole card: "Each removes a silent outcome or uses the code that names what actually went wrong."

Why (b) lost: Not recorded, beyond the card's statement of the problem: macOS and Windows merge the two directories.
