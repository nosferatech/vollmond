## Question

Every fixture store needs a `.vmd/config.yaml`. §9.1 showed a full example, §5.7 makes strict uniqueness the default, and §9.1
says a record in no collection is valid. Still open was whether `collections` and `ignore` may be left out, and whether the line
`vmd: 1` is required (suite question 15). The suite's sample stores have a configuration holding the single line `vmd: 1`; if
that is not valid, every fixture store needs more boilerplate. What is the smallest valid store configuration?

## Options

- **(a) Only `vmd: 1` is required.** Chosen, as recommended. Every fixture store starts with a one-line configuration, and
  everything else defaults (strict uniqueness, no collections, nothing ignored). A missing or unknown `vmd` value is an error,
  which leaves a format version that a future vmd 2 can rely on.
- **(b) Even an empty file is valid.** Any directory with a `.vmd/config.yaml` is a store, which is the least typing. There is no
  version marker, so a later format change cannot tell an old store from a new one except by guessing.
- **(c) `collections` is required too.** Every store must also say `collections: {}` even when it has none. More boilerplate in
  every fixture and every new store, and nothing gained.

## Decision

(a). A `.vmd/config.yaml` holding only `vmd: 1` is a valid store, with strict uniqueness and no collections.

## Why

The card's reason: as the suite recommends, and what the samples already assume. (b) leaves no version marker for a later
format change; (c) adds boilerplate and gains nothing.
