## Question

An unknown `<word> data` fence, such as `toml data`, is `feature-unsupported` only right after a heading (Appendix D: "after a
heading"). As the first block of a record without a title heading, or right after a data block, the Markdown parser (#79, its
second open reading) reads it as prose. Is a newer kind of data block detected there too?

## Options

- **(a) `feature-unsupported` wherever it appears**, so a newer kind of data block is always detected. Chosen, as recommended.
- **(b) Keep the draft as it is.** In the two other places the fence is prose, so an older reader reads a newer kind of data block
  as text.

## Decision

(a), as part of card P's option (a), accepting every recommendation: an unknown `<word> data` fence is `feature-unsupported`
wherever it appears: after a heading, as the first block of a record without a title heading, and right after a data block.

## Why

The card's reason: it applies "G3's rule that every addition is detectable", which is [G3a](G3a.md) here, so a newer kind of
data block is always detected. The card's account of (b): "Today it's prose there".
