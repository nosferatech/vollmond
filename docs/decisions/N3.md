## Question

Is the value of a repeated member checked, as in `{"a": 1, "a": {"$ref": 1, "x": 1e400}}`? The JSON parser (#69) reported only
`duplicate-member` meanwhile: "every error reported" (C2) and "no node for the repeat" pull in different directions.

## Options

- **(a) Do not look inside the repeat.** Chosen, as recommended. The JSON parser already does this.
- **(b) Look inside and report its issues.** The only path they could be reported at is the first member's, which would point at
  the wrong node.

## Decision

(a), with card N's option (a), accepting every recommendation. A repeated member's value is not looked into (§4.1, Appendix D),
with a case.

## Why

The card's reason: the only path an issue inside the repeat could be reported at is the first member's, which would point at the
wrong node (b); once the duplicate is fixed, a re-run shows the rest. For the card as a whole: each rule follows YAML or C2 where
they speak, and picks the safe reading where they don't.

## Applied in

Draft v0.9 (#73, `75c8728`), §4.1 and Appendix D; the YAML parser (#72, `24689e7`) does the same.
