## Question

From the references pull request (#99). Every read vmd does has a byte limit, the storage contract's bounded reads: 1 MiB for
configuration and schemas, 16 MiB for a record (§11.2). The alias file `.vmd/aliases.jsonl` has none: the I2 design chose to read
it whole (`docs/design/i2-validate.md`, section 2.7). It grows with every rename until it is pruned ([F8](F8.md)), and `check` and
every reference read it. #99 asked whether it should have one.

## Options

- **(a) 16 MiB, like a record.** Chosen, as recommended. The card: "A larger file is `alias-file-invalid`, an existing code, with
  a message naming the limit and suggesting a prune. At about 100 bytes a line, that is over 150,000 aliases. Draft v0.13 and a
  suite case."
- **(b) No limit.** The card: "As the design says today. A huge alias file slows every `check` without any message."

## Decision

(a): `.vmd/aliases.jsonl` is read with a bound of 16 MiB. A larger file is `alias-file-invalid`, with a message that names the
limit and suggests `vmd alias prune`. §11.2's bounded reads and Appendix D say so, and §13.6 restates it.

## Why

The card's reason: "It matches every other file vmd reads, and the message points at the remedy."

Why (b) lost: Not recorded. The card's consequence for it: a huge alias file slows every `check` without any message.

## Applied in

Draft v0.13 (#102): §11.2 ("Bounded reads"), §13.6, §19.1, Appendix D `alias-file-invalid`. No suite case, although the card's
option named one: a case file of more than 16 MiB is too large to keep in the suite, so §19.1 lists it with the inputs the suite
leaves out, as for [X3](X3.md)'s paths that differ only in case, and implementations test it on their own. The code follows #99 in
a follow-up pull request.
