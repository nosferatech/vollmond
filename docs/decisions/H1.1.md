## Question

Item 1 of card H1, from #52 Q1 and #54 Q12. Appendix D attaches an issue about a whole record (a syntax error, several YAML
documents, a syntax error in front matter) to "the record", while the suite README's Expected issues section said `at` is `null`
"as for a syntax error that leaves no value view". Where is `at` for such an issue? The answer blocked the syntax-error cases of
whole JSON and YAML records.

## Options

- **(a) `at` is `""`, the root, and the README is fixed.** Chosen, as recommended. Appendix D's own `path-invalid` row ("`at` is
  null for an asset") already implies it.
- **(b) `at` is `null`, as the suite README said.**

## Decision

(a), with card H1's option (a), accepting every recommendation. An issue about the whole record has `at` `""`, not null, also for
a syntax error that leaves no value view. `null` is only for an issue with no node. The suite's README said null and is fixed
(Appendix D, conformance README).

## Why

The reason in #52 Q1: Appendix D attaches structural errors "where it sits", and uses `null` only for issues that belong to no
record (and for assets in `path-invalid`); #54 Q12 adds that `""` is how "the record" reads for `path-invalid`, where only an
asset gets `null`. Card H1's reason for accepting every recommendation: each keeps vmd strict and its output readable back, and
none contradicts an earlier decision. Why (b) lost: Not recorded.
