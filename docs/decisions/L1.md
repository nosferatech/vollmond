## Question

The conformance runner (#65) picked a default for ten gaps where the suite README was silent, and its reviewer judged each
sensible. They were written into the README marked "to be confirmed":

- a case file that cannot be read is reported as an `error` under the id `<file>/`;
- a malformed case counts as selected if the selection cannot be evaluated on it;
- an undefined operation's case still has its unknown members rejected;
- of `query`'s parameters, only the five listed are compared, and the rest are unknown;
- a partial run leaves `unused_skips` out;
- a runner's declaration needs `name`, `version` and `profiles`;
- a selection is invalid by the rules the runner states;
- a missing `cases/` directory stops the run (exit 2);
- a BOM in a case file is rejected;
- `suite.commit` is left out when the checkout has changes.

Are they rules for every runner?

## Options

- **(a) Confirm all ten as written.** Chosen, as recommended. The README defaults lose their "to be confirmed" marks.

Other options: Not recorded.

## Decision

(a), with card L's option (a), accepting every recommendation. The ten runner defaults of the suite README's section on the points
the first runner settled (formerly "Defaults where this README is silent", #65) are confirmed. Their marks "(runner default, to be
confirmed by the project owner)" are gone, and they are rules for every runner.

## Why

The card's reason: each default is the safe one, and the reviewers checked them.

Why the other options lost: Not recorded.

Draft v0.8 (#67, `26a1a55`): the suite README's section is now "Points the first runner settled", without the marks.
