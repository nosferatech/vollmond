## Question

Draft v0.15 (#122) applies the owner's answers to cards AC (old names locked while their alias lasts), AE (schema cost) and AH
(renaming back). The card: "Where your answers on AC (old names locked while their alias lasts), AE (schema cost) and AH
(renaming back) left a detail open, Draft v0.15's author decided it and labelled it "Agent's reading, for the owner to confirm".
Confirming makes them decided; any you reject becomes its own card. Three have a cost a user would notice (marked)." The card
lists eight:

1. **The refusal has no error code yet** ([AC](AC.md) reading 1). The card: "When a write is refused because an alias holds the
   name, the message names the alias and suggests `vmd alias prune`; the code is named when the lock is built (phase I5)."
2. **Which writes are locked (cost)** (AC reading 2). The card: "Every vmd operation that creates a name: rename, mv, new,
   insert, and also set (a new field) and body (new text with a block anchor). Raw storage writes (`write`, `edit`) are not
   locked: like a plain editor they go through, and the `alias-shadowed` warning catches them. Example: with alias `setup` →
   `install`, `vmd set doc.json#setup 1` is refused, but a raw write of the same file is only warned about."
3. **Which names are held** (AC reading 4). The card: "Those recorded under the record's current path and its old paths, the same
   set that decides where an old link goes: an alias recorded in `a.md` before it moved to `b.md` still locks the name in `b.md`."
4. **A writer must read the alias file (cost)** (AC reading 5). The card: "An implementation that only writes, without
   validating, must still read `.vmd/aliases.jsonl` to refuse locked names."
5. **Alias names are anchor names** (AC reading 6). The card: "An alias's old and new names must look like anchors (a letter,
   then letters, digits, `_` or `-`), so `$title` can never be one. The code already works this way."
6. **What "obviously should be refused" means (cost)** ([AE](AE.md)'s reading). The card: "Only the refusals vmd already has:
   over 1 MiB, not a valid schema, or vmd keywords breaking the spine rules. No complexity cap, so a small but slow crafted schema
   is accepted, and a service validating untrusted data sets its own time budget. If you meant an extra cap, reject this one."
7. **Renaming back through a longer chain** ([AH](AH.md) reading 1). The card: "After `a` → `b` → `c`, renaming `c` to `a`
   counts as a rename back: it drops `a` → `b` and records `c` → `a`; `#b` still reaches the section."
8. **Moving a record back** (AH reading 2). The card: "Moving `b.md` back to `a.md` while `a.md` → `b.md` lasts is allowed the
   same way, and turns the alias around."

The card's items point at the records' readings; the numbers in parentheses are the records', added here.

## Options

- **(a) Confirm all eight.** Chosen, as recommended. The card: "The labels come off in the next draft. Nothing in the code
  changes now; the lock is built in I5."
- **(b) Confirm, except what the note says.** The card: "Each exception becomes its own card."
- **(c) Discuss first.** The card: "The readings stay labelled."

## Decision

(a): all eight readings are confirmed. The records that hold them, AC (its readings 1, 2, 4, 5 and 6), AE and AH (its readings 1
and 2), say so. AC's reading 3 points at cards AH and AI, which decided its two cases, and was not on the card.

## Why

The card's reason: "Each follows the safe side of your answers or what the code already does. Item 2 is the one to look at
twice: it lets raw file writes through the lock, warned, rather than making storage writes understand names. Item 6 is your open
AE question."

Why (b) and (c) lost: Not recorded.

## Owner's note

The project owner chose (a) on the review desk on 2026-10-13, with no note.
