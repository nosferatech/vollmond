## Question

Item 4 of card J, from the independent review of #58. YAML forbids a U+FEFF in plain scalars and keys, but the `yaml` library
accepts it silently. The library also strips one at the start of any text it is given, so front matter or a `yaml data` block
starting with U+FEFF would read as if it were not there. What is a U+FEFF in YAML away from byte 0?

## Options

- **(a) Wherever YAML does not allow the character, including the start of front matter or of a data block, it is a
  `syntax-error`.** Chosen, as recommended.

Other options: Not recorded.

## Decision

Card J's option (a), accepting every recommendation. U+FEFF in YAML is a `syntax-error` wherever YAML does not allow the
character, including the start of front matter or of a `yaml data` block (§5.1). YAML itself would read a U+FEFF at the start of
a document as a byte order mark (YAML 1.2.2, section 5.2); vmd allows one only at byte 0 of the file. §5.1 notes the trap of the
`yaml` package, which strips a leading U+FEFF from any text it is given and accepts one in a plain scalar (measured with 2.9.1).
This narrows [I1.4](I1.4.md), under which a U+FEFF away from byte 0 was an ordinary character.

## Why

The card's reason: it keeps "a BOM only at byte 0" true. For the whole card: each recommendation "keeps one rule per thing and
matches what the libraries vmd builds on can check".

Why the other options lost: Not recorded.
