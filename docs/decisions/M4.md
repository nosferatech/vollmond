## Question

`list` or `grep` over a file the backend cannot read leaves the file out and still succeeds, with a `storage-failed` error beside
the result, so none vanish silently (§12.2). The design said a success can carry warnings, and was silent on errors. The storage
contract and filesystem backend (#68) asked whether to leave such files out on a successful page with an error-severity issue, or
fail the whole operation, and left them out meanwhile.

## Options

- **(a) Allow it.** Chosen, as recommended. The command's exit code is then 4 (§12.3), as for `check`, so a script notices.
- **(b) Fail the whole operation**, the alternative #68 named.

## Decision

(a), with card M's option (a), accepting every recommendation. A successful operation may carry an error, such as an unreadable
file that `list` or `grep` leaves out, and the command then exits with 4 (§12.3, Appendix D's preamble, §11.2).

## Why

The card's reason: the file does not vanish silently, and exit code 4 lets a script notice. For the card as a whole: each rule
gives one meaning in every language and engine, which is what portable is for.

Why the other options lost: Not recorded.
