## Question

[C19](C19.md) decided that a selector matching nothing returns an empty result. The draft made a many-reference
(`cardinality: many`) whose selector matches nothing a dangling reference, an error that cannot be lowered, so C19's own
example, a ticket with no decisions yet, would fail `check`. Is a many-reference that matches nothing an error? The question came
from the independent review of #50 (Draft v0.4).

## Options

- **(a) It is fine, with no targets.** Chosen, as recommended. An empty many-reference has status `ok` and no targets,
  consistent with C19. A schema that needs at least one target says so (`minItems`-style).
- **(b) A configurable warning.** Flags it by default but lets a store turn it off.
- **(c) Dangling, an error, as drafted.** Strict, but C19's example fails validation.

## Decision

(a): an empty many-reference is valid (§8.5).

## Why

The card's reason: it is consistent with C19, and a schema can still require targets. (c) would make C19's own example fail
validation. Why (b) lost: Not recorded.

## Applied in

Draft v0.4 (#50, `1043a6c`), §8.5. [I1.8](I1.8.md) later made a many-reference to a record that does not exist `ref-dangling`,
keeping the empty result for a record that exists with nothing matching.
