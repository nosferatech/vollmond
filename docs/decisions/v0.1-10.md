## Question

How does an app on AWS read a store hosted on GitHub, and how fresh must it be? The review proposed publishing the index (and the
content) on push rather than querying GitHub live: a push triggers an incremental re-index, the result goes to S3, and the site
reads from there. It asked whether the site is read-only or must write too, and how fresh it must be.

## Options

- **(a) Publish the index and the content on push.** Chosen, as the review recommended. The site reads from S3; freshness is
  seconds to a minute, at close to no cost.
- **(b) Query GitHub live**, through the trees API and GraphQL. It works for small sites, but every field query then means parsing
  every file, plus rate limits and 100 to 500 ms per call.

## Decision

(a). Incremental index updates are wanted. Eventual consistency is fine, but propagation should take a low number of seconds, not
minutes. The website is mainly read-only; creating tickets from it would be nice.

## Why

The session's reason for (a), in its review: querying GitHub live means parsing every file for every field query, with rate
limits and 100 to 500 ms per call, while a published index costs close to nothing.
