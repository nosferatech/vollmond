## Question

For read commands, issues are about the read, so the CLI foundation (#74) printed them on stderr and the result on stdout. For
`check` (phase I2), the issues are the result. Where do issues go?

## Options

- **(a) Issues go to stderr, except for commands whose result is the issue list (`check`, `refs`)**, which print them on stdout;
  the spec says so in §12.3. Chosen, as recommended.

Other options: Not recorded.

## Decision

(a), with card O's option (a), accepting every recommendation. Issues go to stderr. `check`, whose result is its issues, and
`refs`, whose result lists references with their status, print those on stdout; configuration issues and the warning about the
runtime's Unicode data still go to stderr for them (§12.3).

## Why

The card's reason for the card as a whole: each rule makes the CLI predictable for agents and keeps anchors stable across Node
versions.

Why the other options lost: Not recorded.
