## Question

A root whose `$body` starts with a `---` line cannot be written back without opening front matter, as the fixture
`front-matter/not-at-the-start` parses to. The Markdown fixtures (#54, questions 4 and 5) found the gap: §5.8 did not list such a
value among those it refuses, and a root with no fields has no Markdown form for it. How is it written?

## Options

- **(a) The writer writes empty front matter (`---` and `---`) first,** which by [H3.5](H3.5.md) reads back as no fields.
  Chosen, as recommended.
- **(b) §5.8 lists such a `$body` among the values the serializer refuses.**
- **(c) The serializer escapes it.**

## Decision

(a), as card H3's option (a), accepting every recommendation. A root whose `$body` starts with `---` is written with empty front
matter first (§5.8).

## Why

The card's reason: the empty front matter reads back as no fields, so the value round-trips. Why the other options lost: Not
recorded. The card's note for all sixteen items: each recommendation keeps vmd strict and its output readable back, and none
contradicts an earlier decision.
