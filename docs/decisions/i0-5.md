## Question

The owner had enabled a ruleset on `main` that blocks deletion and force pushes and requires linear history, and asked which other
settings a public repository needs, not knowing the defaults for external contributors. The session listed what was already set
well (outside contributors can only open pull requests from forks, squash merging only, a read-only workflow token, approval of a
first-time contributor's workflow runs, secret scanning, Dependabot alerts, private vulnerability reporting) and proposed five
additions.

## Options

1. **Require a pull request before merging, with 0 required approvals.** GitHub never lets the owner approve their own pull
   request, so a required approval would block every merge the owner makes; the agents' direct pushes to `main` would also go
   through pull requests.
2. **Require the `check` status from CI to pass**, without which "merges once CI passes" is only a convention.
3. **Delete branches automatically after a merge**, since agents create one per task.
4. **Turn on Dependabot security updates**, with a `dependabot.yml` for GitHub Actions to keep pinned commit hashes current.
5. **Optional: turn off the wiki**, since the documents live in the repository, and add `SECURITY.md` and `CONTRIBUTING.md`
   before inviting outside contributions.

The owner chose all five.

## Decision

`main` accepts only pull requests (no required approvals, since the project owner cannot approve their own; squash merges only)
that pass the CI check, with no deletion, no force push and linear history. Merged branches are deleted, the wiki is off,
Dependabot security updates are on, and `SECURITY.md` and `CONTRIBUTING.md` describe reporting and contributing.
