## Question

F4's interim rule said that a client warns when it reads a store whose version it does not support, while the owner's F1 note
said that a reader on an incompatible version must fail loudly. The two differ for an older client reading a newer store, which,
after a change to the slug rule for example, can misread it silently. What does a client do with a store on a different format
version? The question came from the independent review of #50 (Draft v0.4).

## Options

- **(a) Newer store: refuse; older store: warn.** Chosen, as recommended. A client that does not know a store's version refuses
  to read it, with an error it cannot be configured away, because it cannot know the new rules. A client reading an older
  version it still understands warns. The full design, transcoding included, stays in #46.
- **(b) Warn in both cases, as drafted.** Nothing stops a client from reading data whose rules it does not know, so a change to
  the slug rule could silently resolve links to the wrong place.

## Decision

(a), with the owner's note: for a major difference, a client reads and writes at the store's level if it supports that level,
and otherwise refuses a newer store and warns on an older one. A minor difference gives no warning, and any change that is not
compatible both ways is a major version.

## Why

The card's reason for (a): it is the fail-loudly half of the owner's F1 note, the half the interim rule can already guarantee.
(b) lets a client read data whose rules it does not know.

## Owner's note

> If client can, should also set compatibility level on the reader, if difference is in major version.
> For minor version difference, if compatibility of back and forth between newer and older minor version formats is guaranteed,
> a warning should not be needed.
