## Question

Item 2 of card I1, from #57's open questions (#53 question 9, the first half, which [H4.4](H4.4.md) left open): how does a
canonical address percent-encode characters outside `step`, such as a key `a/b`, or a name with a space or `é`? Which hex case,
and which encoding?

## Options

- **(a) UTF-8 with upper-case hex, encoding exactly what RFC 3986 does not allow in a fragment, plus `/` and `%`.** Chosen, as
  recommended. A canonical address has one spelling.

Other options: Not recorded.

## Decision

Card I1's option (a), accepting every recommendation. A canonical address percent-encodes, as UTF-8 with upper-case hex, exactly
the characters RFC 3986 does not allow in a fragment, plus `/` and `%` (§7.1). So that every such address matches the grammar,
`step` now accepts every fragment character except `/`, where Draft v0.5 allowed only letters, digits, `-`, `_`, `.`, `$` and
escapes. The log records that widening as the agent's, so that the rule and the grammar agree.

## Why

The card's reason: so that a canonical address has one spelling. For the whole card: each recommendation "keeps vmd strict without
rejecting data that is plainly fine".

Why the other options lost: Not recorded.
