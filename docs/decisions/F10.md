## Question

The owner's answer to [C25](C25.md) settled ordering: path bytes, exact UTF-8, then document order, and never across documents.
Case-insensitive matching was still open, such as `status:open` matching `Open`, and it needs a rule for non-ASCII letters.

## Options

- **(a) Unicode simple case folding.** Chosen, as recommended. One character to one, so Greek and Cyrillic pairs match, while
  Straße does not match STRASSE. The same in every language; JavaScript needs a small folding table.
- **(b) ASCII only.** A to Z fold, everything else matches exactly. Simplest, but ΑΘΗΝΑ does not match Αθηνα.
- **(c) Leave it to the VQL fixture task (#34).** The evaluator (I3.2) starts without a rule.

## Decision

(a). Case-insensitive matching uses Unicode simple case folding.

## Why

The card's reason: deterministic everywhere, and it covers most scripts. (b) leaves non-ASCII letters unmatched; (c) leaves the
evaluator without a rule.
