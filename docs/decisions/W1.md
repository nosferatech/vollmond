## Question

log marks each one "Agent's reading, for the owner to confirm". The card lists those details:

1. `block-anchor-class` (validation error) names [P5](P5.md)'s code.
2. P5: a block anchor with a `class` keeps its `id` as the anchor, so links to it still resolve.
3. `field-not-computed` (warning) names [S5](S5.md)'s warning. It is interim, until I2 computes `@refs` and `@collection`.
4. [P2](P2.md) covers both data markers. The card named `yaml data`; an unclosed `json data` fence fails as JSON anyway.
5. An unknown `x-vmd-*` keyword stays `feature-unsupported`, as §9.3 already said. Every other unusable schema is
   `schema-invalid`. [U12](U12.md)'s refusal applies to both: a read fails with the code its schema got.

7. [V1](V1.md)'s timing: the engineering manager had V1 put into v0.11 rather than a later draft, since the owner had decided it
   and the PR was open.

   may stand wherever JSON allows white space. A `jsonc data` block of only comments gives no fields. `jsonc data` blocks need no
   member.
9. [U4](U4.md) and the index: the owner's lightweight case is the per-user cache. The published index (§14.4, §16) is one place an
   advanced backend may keep it. How a backend keeps it is §20's open question 8.
