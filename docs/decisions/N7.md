## Question

The issue for a member whose name has an unpaired surrogate goes at the object ([H1.3](H1.3.md)), but issues inside its value
would carry the lone surrogate in their path, which cannot be written as UTF-8: the JSON parser (#69) found that
`{"\ud800": 1e400}` gives an issue whose `at` is not a well-formed string. Is the value looked into?

## Options

- **(a) Do not look inside its value**, as for a repeated member ([N3](N3.md)). Chosen, as recommended.
- **(b) Look inside it.** Its issues would carry the lone surrogate in their path, which cannot be written as UTF-8.

## Decision

(a), with card N's option (a), accepting every recommendation. For a member whose name holds an unpaired surrogate, its value is
not looked into (§4.1), with a case.

## Why

The card's reason: issues inside the value would carry a path that cannot be written as UTF-8 (b). For the card as a whole: each
rule follows YAML or C2 where they speak, and picks the safe reading where they don't.

## Applied in

Draft v0.9 (#73, `75c8728`), §4.1; the JSON and YAML parsers (#72, `24689e7`).
