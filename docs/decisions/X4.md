## Question

Item 4 of card X, from I2's configuration pull request (#91) and its independent review, which found nothing blocking. The code
keeps its current reading of each item until the owner decides. Globs with `.` or `..` segments (`match: ["../*.md"]`). Store
paths never contain those segments, so such a glob silently matches nothing. There is no traversal, because globs only filter
listed paths. What is such a glob?

## Options

- **(a) `config-invalid`, an existing code.** Chosen, as recommended, "since a glob that can never match is a mistake". Under
  [U21](U21.md), allowing them later would be a minor addition.
- **(b) Keep today's reading: the glob silently matches nothing.** As the code does until the decision.

## Decision

(a), as part of card X's option (a), accepting every recommendation: a glob with a `.` or `..` segment is `config-invalid`.

## Why

The card's reason for the whole card: "Each removes a silent outcome or uses the code that names what actually went wrong."

Why (b) lost: Not recorded, beyond the card's statement of the problem: such a glob silently matches nothing.
