## Question

Item 5 of card J, from the independent review of #58: three details of the byte order mark rule of [I1.4](I1.4.md). Is a BOM a
column? What does a write do with one? Which files does the rule cover?

## Options

- **(a) A BOM is not a column, so line 1's first character is column 1, while offsets still count its bytes; a write keeps a
  file's BOM, and files vmd creates have none; the rule covers every file vmd reads, `.vmd/config.yaml` and schemas included,
  not only records.** Chosen, as recommended.

Other options: Not recorded.

## Decision

Card J's option (a), accepting every recommendation. A byte order mark is not a column, so line 1's first character is column 1,
while offsets count its bytes (§5.1, §5.9). A write keeps a file's byte order mark, and files vmd creates have none (§13.3). The
rule covers every file vmd reads, `.vmd/config.yaml` and schemas included (§5.1).

## Why

Not recorded for the items themselves. For the whole card, the card's reason: each recommendation "keeps one rule per thing and
matches what the libraries vmd builds on can check".
