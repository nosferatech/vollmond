## Question

[K8](K8.md) reads a JSON or YAML section's `$title` as if it followed `## `. The review of the section keys and anchors (#82) found
three cases where the same section then gets a different key in Markdown than in JSON or YAML, which breaks §5.5's promise that a
section keeps its key when its record changes format:

- a title with a line break: Markdown gives `one-two`, while K8 as written keeps only the first line, `one`;
- a title ending in ` #` from a setext heading: Markdown gives `foo-`, while K8 strips it as a closing sequence, `foo`;
- a title using a reference link, `[Foo][bar] baz`, with `[bar]: /x` in the record: Markdown gives `foo-baz`, while K8 does not
  see the definition, `foobar-baz`.

How does a data `$title` become a key?

## Options

- **(a) Read it as a heading's inline content**, with the record's link reference definitions in scope, line breaks as soft breaks
  ([H5.1](H5.1.md)), and no closing sequence stripped. Chosen, as recommended. It gives the same key as Markdown for every record
  that came from Markdown, and equals K8 for every simple title.
- **(b) K8 as written.** The three cases keep giving a section different keys in different formats.

## Decision

(a), as part of card Q's option (a), accepting every recommendation. This refines K8.

## Why

The card's reason: each section keeps one key across all three formats. (b) breaks §5.5's promise for the three cases.
