## Question

This is about the owner's versioning rule ([G3a](G3a.md)). §9.1 allows a minor version to add only a new `$` member, a new `data`
info string or a new `x-vmd-*` keyword. That leaves out new configuration members, and relaxing a refusal later ([U2](U2.md),
[U8](U8.md), [U14](U14.md)). The first version of the design counted any relaxed error as an addition. The review showed that this
loses detectability, since a best-effort reader reads past validation errors (§9.5): if 1.1 accepted a space in `date-time`, a
1.0 reader's `check` would report it, but its `query` would return the record and compare the value wrongly. What counts as a
minor-version addition, and what is an unknown configuration member?

## Options

- **(a) Additions are relaxations of refusals no reader reads past.** Chosen, as recommended. §9.1's list becomes "any construct
  the previous minor version refuses so that no reader returns data that holds it": a structural error, an operation error that
  fails the operation (an invalid configuration), or an invalid schema under [U12](U12.md)'s (a). Relaxing a validation error
  needs a major version. An unknown configuration member is `feature-unsupported`, naming the store's version.
- **(b) Keep the three forms.** An unknown configuration member is `config-invalid`; a new member or any relaxation needs a major
  version or a new keyword.
- **(c) Ignore unknown configuration members.** An older reader would misread a newer store silently.

## Decision

(a). It widens G3a's rule that an addition qualifies only as one of three forms: any construct the previous minor version
refuses so that no reader returns data that holds it is now an addition, and an unknown configuration member is
`feature-unsupported`, whose message names the store's declared version.

## Why

The card's reason: "It keeps §9.1's reason (an older reader fails rather than misreads) while letting configuration grow by
minor versions. It depends on U12's (a). It is the kind of versioning burden you asked me to surface; this is my best attempt to
keep it small." The design adds that the existing `x-vmd-*` form has the same exposure as any schema construct, since an unknown
keyword only makes the schema invalid, and U12's (a) is what keeps every reader from returning the collection's data; with U12's
(b) it would not be detectable either. The card's consequence for (c), not a reason it gives against it: an older reader would
misread a newer store silently.

Why (b) lost: Not recorded.
