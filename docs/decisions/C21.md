## Question

§8.1 lists Markdown links as a reference form. Two places hold Markdown that is not a Markdown file's body: a heading's `$title`,
and the `$body` string of a YAML or JSON record, which is Markdown prose stored as data (suite question 18, second item). For
example, the heading `## See [§4.6](design.md#contiguous)`, or in a YAML record `$body: See [the log](../docs/log.md#room)`. When
`design.md#contiguous` is renamed through vmd, is this link rewritten?

## Options

- **(a) Yes, both.** Chosen, as recommended. Links are extracted wherever Markdown text appears, in `$title` and in every `$body`,
  so `rename` and `mv` rewrite them and check reports them when dangling. A ticket converted from `.md` to `.yaml` keeps its
  tracked links. A link in a title is located by an offset into `$title`, as links in prose are by an offset into `$body`.
- **(b) Only in the `$body` of Markdown files.** Extraction is simpler, but converting a ticket from `.md` to `.yaml` silently
  stops tracking its links, and a link in a heading breaks on rename with no warning.

## Decision

(a). Links in titles and in YAML or JSON prose are tracked references.

## Why

The card's reason: as the suite recommends; both strings are Markdown, so treating them alike is the least surprising rule. (b)
silently stops tracking links when a record changes format, and lets a link in a heading break on rename.
