## Question

Item 12 of card I1, from #57's open questions: two literal readings of §4.3 to confirm. Is the int64 string `"-0"` accepted, and
does the number `1.0` count as an int64?

## Options

- **(a) The string `"-0"` is accepted and written as `"0"`, and the number `1.0` counts as an int64.** Chosen, as recommended.
  JSON Schema's `integer` accepts `1.0`, though by [G1](G1.md)'s integer-by-form rule it is not written as one.

Other options: Not recorded.

## Decision

Card I1's option (a), accepting every recommendation: int64 accepts the string `"-0"`, written without the sign, and the number
`1.0`, as JSON Schema's `integer` accepts it (§4.3). The card said that `"-0"` is written as `"0"`; the log corrects this: the
canonical int64 form writes a value within ±(2^53−1) as a number, so the writer writes the number `0`, and the string on the card
was a slip of the session that drafted it.

## Why

The card's reason for `1.0`: JSON Schema's `integer` accepts it. For the whole card: each recommendation "keeps vmd strict without
rejecting data that is plainly fine".

Why the other options lost: Not recorded.
