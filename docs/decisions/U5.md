## Question

Two collections' globs can both match one file, and §9.1 does not say what happens. What does?

## Options

- **(a) A new validation error, `collection-conflict`.** Chosen, as recommended. The record gets the error and is read
  unschematized. Other records are unaffected. Appendix D gains the code.
- **(b) `config-invalid`.** Every command fails once such a file exists: one new file breaks the whole store.
- **(c) The first collection by name wins.** Silent, and the outcome depends on how collections are named.

## Decision

(a): a record that two collections match gets the validation error `collection-conflict` and is read unschematized; §9.1 says
what a conflict does, and Appendix D gains the code.

## Why

The card's reason: "Reports the mistake where it is, without breaking the store or picking silently." The design: (b) lets one
new file break the store, and (c) depends on names.
