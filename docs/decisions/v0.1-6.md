## Question

Draft v0.1 disclaimed a query language, but the index needs one. The review said a Belfry-style `field:value` filter covers the
common case; the session's review in chat added that the index was already SQLite, that agents write SQL reliably, and that
read-only SQL views would cover the rest at almost no cost. What must the query language be?

## Options

- **(a) A Belfry-style `field:value` filter** for the common case.
- **(b) Read-only SQL views** over the SQLite index, beside the filter.

## Decision

The query language should be platform-independent: a backend without git or SQLite should be able to implement at least the core,
and interpreters should be feasible in several programming languages. A simple `key:value` language with and/or may suffice; SQL
is acceptable if libraries exist or an interpreter is feasible.

## Why

The owner's requirement: an implementation that uses neither git nor SQLite should be able to implement at least the core of the
language, in several programming languages, and SQL qualifies only where libraries exist or an interpreter is feasible. Why the
other options lost: Not recorded.
