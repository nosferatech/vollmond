## Question

Before VQL fixtures can be written (#34), results need one order and string matching one rule. §10.5 broke sort ties "by
address" without saying how addresses compare, and §10.3 said comparisons ignore case without saying how for non-ASCII text.
Totals that may be estimates, the default fields, and how full text splits into words were also open (suite question 17). For
example, two tickets have severity High, `tickets/0171-x.md` and `tickets/0020-y.md`: which comes first? And does
`status:STRASSE` match a status of Straße?

## Options

- **(a) Path bytes, then document order; simple case folding.** Recommended. Ties are ordered by store path compared as bytes
  (0020 before 0171), then by the node's position in its file. Strings are compared after Unicode simple case folding, one
  character to one, so Greek and Cyrillic case pairs match but Straße does not match STRASSE. Deterministic in every language;
  JavaScript needs a small folding table, since `toLowerCase` is not the same thing. Totals, default fields and word splitting
  are settled in #34.
- **(b) Full case folding or locale-aware sorting.** Straße matches STRASSE and sorting follows a human alphabet, but results
  vary with ICU versions and locales, so fixtures cannot state one exact answer and two implementations may disagree.
- **(c) Leave all of it to #34.** Nothing is decided now, and the VQL fixture task picks and records the rules. Likely the same
  outcome later, but the evaluator (I3.2) has no rule to start from.

Chosen: neither in full. The owner answered Other: path bytes, with an invariant collation, exact UTF-8, and no sorting across
documents. The letter case was left open, and the follow-up [F10](F10.md) settled it.

## Decision

The owner's answer: sort ties are ordered by store path, compared as exact UTF-8 bytes, then by document order within a record,
never across records. Case-insensitive matching is [F10](F10.md)'s.

## Why

The owner's reason: an invariant collation on the exact UTF-8 representation gives every path that differs in encoding a unique
order, and sorting within a document never crosses documents. The card's reason for (a): exact, repeatable results matter more
for agents and fixtures than linguistic niceties. (b) gives results that vary with ICU versions and locales; (c) leaves the
evaluator without a rule.
