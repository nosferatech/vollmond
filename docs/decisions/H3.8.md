## Question

What is a second `yaml data` block right after a section's data block? The Markdown fixtures (#54, question 7) asked with
`## Part`, a data block with `owner: ana`, then a second data block with `runs: [R0007]`, then text.

## Options

- **(a) Prose,** read literally ("a fenced block anywhere else is prose"), so `$body` begins with a data fence.
- **(b) A structural error, as `data-block-misplaced` at the section.** Chosen, as recommended. "There is at most one", and the
  Draft v0.2 decision log says data blocks elsewhere in a section are not supported.

## Decision

(b), as card H3's option (a), accepting every recommendation. A second data block right after the first is
`data-block-misplaced` at its section.

## Why

The PR's reason: as prose, its fields vanish silently, and §5.8 already refuses a `$body` that begins with a data fence. The card
adds that the Draft v0.2 log already leans that way: "Data blocks elsewhere in a section are not supported, and probably never
will be: they would break round-trips and the continuity of `$body`." The card's note for all sixteen items: each recommendation
keeps vmd strict and its output readable back, and none contradicts an earlier decision.

## Applied in

Draft v0.5 (#57, `d0d1424`), §5.3 and Appendix D. P6 later made an unknown `<word> data` fence in this place
`feature-unsupported`.
